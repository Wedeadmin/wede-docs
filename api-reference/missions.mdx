## List Missions
Requires `missions:view` permission.

### Response

```json
{
  "data": [
    {
      "id": "uuid",
      "event_id": "uuid",
      "team_id": "uuid",
      "status": "IN_PROGRESS",
      "feedback": null,
      "created_at": "2026-05-27T10:00:00Z",
      "updated_at": "2026-05-27T10:05:00Z"
    }
  ],
  "count": 1
}
```

## Create Mission
Requires `missions:manage` permission.

### Request Body

```json
{
  "event_id": "uuid",
  "team_id": "uuid",
  "notes": "Patient is conscious, use south entrance"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `event_id` | string | Yes | The event this mission responds to |
| `team_id` | string | Yes | The team assigned to this mission |
| `notes` | string | No | Operational notes visible to the team |

Creating a mission fires the `mission.created` webhook and records a billable operation.

---

## Update Mission Status
Requires `missions:manage` or `missions:receive` permission.

### Request Body

```json
{
  "status": "COMPLETED",
  "feedback": "Patient stabilised and transported to Hospital de Santa Maria"
}
```

### Mission Lifecycle
| Status | Description |
|--------|-------------|
| `CREATED` | Mission created, team notified |
| `DISPATCHED` | Team acknowledged and is en route |
| `IN_PROGRESS` | Team is on site |
| `COMPLETED` | Mission concluded |
| `CANCELLED` | Mission cancelled before completion |

Feedback is opaque — the platform stores it but does not parse or validate its content. The team defines the feedback format via their parser configuration.

Status updates fire the `mission.status_updated` webhook.
