## 2. Data We Collect

### 2.1 Account and authentication data

- User name and email (provided at registration)
- Role and access level (RBAC)
- Account creation date and time
- Session history (JWT — expires after 8 hours)

### 2.2 Operational data

- Events created by the Tenant (type, priority, vertical, GPS location, timestamp)
- Team and member data (name, role, availability status, GPS location)
- Missions and their lifecycle (status, delivery channel, timestamps)
- Tenant configuration (parsers, catalog, zones, thresholds)

### 2.3 Device data (offline SDK)

- `device_id` — unique permanent identifier generated by the SDK on installation
- Platform and application version (iOS, Android, web, etc.)
- Offline queue — operations generated without connectivity, with sequence number and generation timestamp
- GPS location — collected periodically when tracking is active (intervals configured by the Tenant)

### 2.4 Audit and security data

- Immutable log of all operations: action, entity, user, IP, NTP timestamp
- Authentication attempts (successful and failed)
- Unauthorised access attempts

### 2.5 What we do not collect

- Event payload content — payloads are opaque; Wede transports them without reading or storing them in an interpretable form
- Biometric data
- Health data (unless the Tenant includes health data in the payload — the Tenant's responsibility)

## 4. Device ID and Offline Queue

### 4.1 What is the device\_id

The `device_id` is a unique identifier generated by the Wede SDK on the first installation on a device. It is permanent — it survives application updates and reinstallations when stored in the operating system keychain/keystore.

### 4.2 Purpose

- Identify the device for offline queue synchronisation
- Guarantee idempotency — the server never processes the same operation twice
- Allow the server to monitor the offline state of each device
- Record in the audit log which operations were generated by which device

### 4.3 Association

The `device_id` is associated with the Tenant and the User who registered it. This association allows the Tenant to manage and monitor its devices. Wede does not share the `device_id` with third parties.

### 4.4 Offline queue retention

Offline queue data is retained locally on the device until server confirmation. After synchronisation:

- **On device**: synced entries may be deleted by the SDK
- **On server**: entries are retained for the plan's retention period (minimum 90 days)

<Note>
  The offline queue contains only operational data (action type, GPS coordinates, vertical, priority, timestamp). It does not contain event payloads.
</Note>

## 5. GPS Location

### 5.1 Collection

GPS location of team members is collected by the SDK when tracking is active. Tracking is activated by the user (team member) themselves or by the Tenant through Platform configuration.

### 5.2 Frequency

- Online: configurable interval by the Tenant (default: 60 seconds)
- Offline/SMS: configurable interval by the Tenant (default: 300 seconds)

### 5.3 Purpose

GPS location is used exclusively to calculate team proximity to the event location (scoring engine), display team positions on the Tenant's dashboard map, and optimise the communication channel based on location.

### 5.4 Access

Only the Tenant and its authorised users have access to location data. Wede does not share location data with third parties.

## 8. Data Subject Rights

Under the GDPR, data subjects have the right to:

- **Access** — obtain confirmation whether their data is processed and access a copy
- **Rectification** — correct inaccurate or incomplete data
- **Erasure** — request deletion of data, subject to legal retention obligations
- **Restriction of processing** — in certain circumstances
- **Portability** — receive their data in a structured, machine-readable format
- **Objection** — object to processing based on legitimate interests

<Warning>
  The audit log is immutable by construction (enforced by a database trigger). The right to erasure does not apply to the audit log, due to legal and security obligations.
</Warning>

To exercise these rights, contact: [privacy@wede.pt](mailto:privacy@wede.pt)

## 9. Security

Wede implements appropriate technical and organisational measures to protect personal data:

- TLS 1.2\+ on all communications
- Passwords stored with bcrypt
- Secrets managed via GCP Secret Manager
- 7-level RBAC with no privilege escalation
- JWT with 8-hour expiry and immediate revocation
- Brute force protection and rate limiting
- Immutable audit log
- Data in EU (GCP europe-west1)
