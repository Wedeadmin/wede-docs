## 2. Service Description

Wede provides offline-first operational continuity infrastructure. The Platform is middleware — an integration layer via API and SDK — that ensures the continuity of critical workflows regardless of connectivity state.

### 2.1 What Wede does

- Receives and delivers operational events with automatic fallback between channels (Internet, SMS A2P, Voice)
- Runs the team scoring engine by GPS proximity, equipment match and availability
- Maintains an immutable offline queue on the device that syncs when connectivity is restored
- Records an immutable audit log of all operations
- Manages the lifecycle of operational missions

### 2.2 What Wede does not do

- Wede does not read, interpret or store the content of event payloads — payloads are opaque by construction
- Wede does not validate the physical state of the Tenant's equipment or resources
- Wede does not replace the Tenant's own communications systems (phone, radio, etc.)
- Wede does not guarantee the availability of third-party channels (SMS operators, voice networks)

<Note>
  Wede is infrastructure, not an end-user application. Operational responsibility always remains with the Tenant.
</Note>

## 4. Offline Delivery Guarantees

### 4.1 Immutable offline queue

The Wede SDK maintains a local queue of operations generated without connectivity. This queue is immutable — data is never deleted from the device until the server confirms receipt.

### 4.2 Idempotency

Each queue entry has a monotonically increasing sequence number per device. The server ensures the same operation is never processed twice, even in case of retransmission.

### 4.3 Synchronisation

When connectivity is restored, the SDK automatically synchronises the queue with the server. Wede guarantees no valid operation is lost during this process.

### 4.4 Limitations

The offline delivery guarantee does not cover hardware failures on the device that prevent reading local storage, operations generated after the Tenant's subscription has expired, or operations that exceed the limits of the active plan.

## 7. Device ID and Offline Queue

### 7.1 Device ID generation

The device\_id is generated by the SDK on the first installation on a device and is permanent. It survives application updates, cache clearing and reinstallations when stored in the operating system keychain/keystore.

### 7.2 Association

The device\_id is associated with the Tenant and the User who registered it. This association is recorded in the audit log.

### 7.3 Queue retention

Offline queue data is retained on the device until server confirmation. After successful synchronisation, synced data may be deleted locally by the SDK. On the server, synchronised entries are retained for the retention period defined in the Tenant's plan.
